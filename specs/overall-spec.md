## 二、用户故事

### US-001：应用启动

> 作为用户用户，我打开tpl-workspace鸿蒙App后，可以看到应用主界面，以便了解应用的基本功能。

**验收标准**：
- 应用启动后加载首页并渲染完成
- 已登录用户直接进入个人中心
- 未登录用户被引导到登录页

### US-002：用户注册

> 作为新用户，我可以使用手机号和密码注册账号，以便创建我的账号。

**验收标准**：
- 用户输入用户名、密码、确认密码
- 输入图形验证码
- 提交后注册成功，提示前往登录
- 注册失败时显示具体错误原因

### US-003：用户登录


**验收标准**：
- 用户输入用户名、密码、图形验证码
- 登录成功后跳转个人中心
- 登录失败时显示错误提示
- 登录状态在应用关闭后的一定时间内保持有效

### US-004：个人中心首页


**验收标准**：
- 页面提供退出登录功能

## 三、功能需求

### 3.1 应用脚手架（FR-001）

| ID | 需求 | 优先级 |
|----|------|:--:|
| FR-001-001 | 系统 MUST 提供应用的启动入口（Ability），加载主页面 | P0 |
| FR-001-002 | 系统 MUST 支持页面路由导航，从首页跳转到各业务页面 | P0 |
| FR-001-003 | 系统 MUST 提供公共工具模块（日志、响应式断点系统） | P0 |
| FR-001-004 | 系统 MUST 支持多屏幕尺寸适配（手机竖屏、手机横屏、平板） | P1 |
| FR-001-005 | 系统 MUST 提供全局主题和样式配置 | P1 |
| FR-001-006 | 系统 SHOULD 提供网络请求拦截器（Token 注入、错误处理） | P0 |
| FR-001-007 | 系统 SHOULD 提供安全的本地存储能力（Token、用户信息） | P0 |

### 3.2 用户认证（FR-002）

| ID | 需求 | 优先级 |
|----|------|:--:|
| FR-002-001 | 系统 MUST 提供用户注册页面，包含用户名、密码、确认密码选择、图形验证码 | P0 |
| FR-002-002 | 系统 MUST 提供用户登录页面，包含用户名、密码、图形验证码 | P0 |
| FR-002-003 | 系统 MUST 在登录成功后存储认证令牌并在后续请求中自动携带 | P0 |
| FR-002-004 | 系统 MUST 在登录成功后跳转到个人中心页面 | P0 |
| FR-002-005 | 系统 MUST 验证注册表单的必填字段和格式约束 | P0 |
| FR-002-006 | 系统 MUST 提供退出登录功能，清除本地认证状态并返回登录页 | P0 |
| FR-002-007 | 系统 MUST 在校验失败时提供明确的错误提示 | P0 |
| FR-002-008 | 系统 SHOULD 在未登录状态下访问需要认证的页面时自动跳转登录页 | P0 |

### 3.3 个人中心（FR-101）

| ID | 需求 | 优先级 |
|----|------|:--:|
| FR-101-003 | 系统 MUST 在数据加载中展示加载状态指示 | P1 |
| FR-101-004 | 系统 MUST 在数据加载失败时展示错误提示并提供重试入口 | P1 |

## 四、非功能性需求

### 4.1 性能

| ID | 需求 | 指标 |
|----|------|------|
| NFR-P01 | 应用冷启动时间 | < 2 秒 |
| NFR-P02 | 页面切换响应时间 | < 500ms |
| NFR-P03 | API 数据加载反馈 | 加载状态在 300ms 后显示 |

### 4.2 安全

| ID | 需求 |
|----|------|
| NFR-S01 | 用户密码在传输过程中必须加密 |
| NFR-S02 | 认证令牌必须安全存储，不可明文暴露 |
| NFR-S03 | 退出登录时必须清除所有本地用户数据 |

### 4.3 兼容性

| ID | 需求 |
|----|------|
| NFR-C01 | 兼容 HarmonyOS API 5.1(19) ~ 6.1(23) |
| NFR-C02 | 支持手机（Phone）和平板（Tablet）设备形态 |

### 4.4 用户体验

| ID | 需求 |
|----|------|
| NFR-U01 | 表单输入应提供即时校验反馈 |
| NFR-U02 | 网络请求失败时应提供用户友好的错误提示 |
| NFR-U03 | 界面文案使用简体中文 |
